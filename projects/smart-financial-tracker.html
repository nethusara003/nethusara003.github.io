THE PROBLEM

Budget apps only show the past.

Why this project exists, and who it’s for.

Most finance trackers are rear-view mirrors: neat charts of money already spent.

The useful question is forward-looking — where is my spending heading? Answering it takes more than CRUD: it takes a model trained on your history, served alongside the app, updating as new transactions arrive.

Smart Financial Tracker pairs a full personal-finance app with an ML forecasting service, so the dashboard doesn’t just report — it predicts.

WHAT I BUILT

Three services, one product.

The engineering decisions that make it work.

01

Three-service architecture

A React + Vite frontend, a Node.js + Express API with Mongoose models and controllers, and a Python Flask ML service for forecasting — each with a clear boundary, orchestrated for local dev with one command.

02

ML forecasting, productized

The Flask service turns transaction history into spending forecasts surfaced directly in the dashboard — machine learning as a feature, not a notebook.

03

Engineering discipline

GitHub Actions CI on every push and Playwright end-to-end tests covering real user flows — the kind of rigor that keeps a multi-service app shippable.

04

Deployed and live

Running in production on Vercel — a real URL, real users, real accountability for uptime and performance.

OUTCOME & LEARNING

What it proved.

OUTCOME

Live production app

Deployed, tested and running — the only project in the portfolio with a public URL and CI guarding every change.

OUTCOME

ML inside a real product

Forecasting isn’t a demo script; it’s a service the UI depends on, with the integration work that implies.

LEARNING

Systems thinking

Multi-service architecture, API contracts between JS and Python, CI/CD pipelines and e2e testing — the full-stack loop from commit to production.
