Vocalis

A local-first text-to-speech studio that turns large documents into downloadable audio — entirely on your own machine. No cloud, no subscription, your text never leaves the device.

ROLESolo developer & designer
STACKElectron · Node.js · FFmpeg
PLATFORMmacOS & Windows desktop
STATUSIn active development
Source code ↗ DESKTOP APP — RUNS LOCALLY, NO LIVE DEMO
THE PROBLEM

Speech shouldn’t require the cloud.

Why this project exists, and who it’s for.

Cloud text-to-speech means subscriptions, an internet connection, and sending your documents to someone else’s servers.

For long documents — study notes, articles, books — that trade-off feels wrong. You want private, free, offline speech: paste text, pick a voice, get audio files you own. Nothing uploaded, nothing metered.

Vocalis answers that by moving the whole pipeline onto the user’s machine: a local backend, local voices, local files. The browser-based editor stays familiar; everything heavy happens locally.

WHAT I BUILT

An offline audio pipeline.

The engineering decisions that make it work.

01

Replaceable local engine layer

A TTS service abstraction with platform workers underneath — a persistent Kokoro MLX worker with a macOS say fallback, and a persistent SAPI PowerShell worker on Windows. Engines can be swapped without touching the app.

02

Chunked generation that survives long texts

Paragraph- and sentence-aware chunking splits large documents, with per-chunk retry and failed-document recovery — a 50-page document doesn’t die on page 49.

03

Batch processing & export

Drop in multiple .txt files, generate WAV or MP3 via FFmpeg, preview with play / pause / seek, and download everything as individual files or one ZIP.

04

A real reading environment

Saved-text library with JSON import/export, reading mode, voice/speed/pitch controls, character & word counters, progress tracking — plus dark mode and a responsive layout.

05

Hardened file handling

Security-reviewed: ZIP path-traversal blocked, symlinks resolved and re-verified inside the output directory, hostile filenames rendered inert. Local software still deserves real security.

OUTCOME & LEARNING

What it proved.

OUTCOME

Fully offline pipeline

End-to-end speech generation with zero network calls — voices, chunking, audio and export all run on-device.

OUTCOME

Fault-tolerant by design

Chunked generation with retry and recovery means long documents complete reliably instead of failing silently.

LEARNING

Desktop architecture depth

Electron main/renderer separation, persistent worker processes, FFmpeg audio pipelines — and why defensive file handling matters even in local apps.
