myagent

A command-line AI agent that turns plain English into actions — calendar lookups, calculations and tool calls, through conversation instead of clicks.

THE PROBLEM

Your calendar shouldn’t need a mouse.

Why this project exists, and who it’s for.

Checking your schedule means opening a browser, clicking through a calendar UI, and scanning for the answer.

That’s slow for something you ask ten times a day. The faster interface is language: “what are my upcoming events?” — asked where developers already live, the terminal.

myagent closes that gap: a conversational agent that understands the request, calls the right tool, and answers in plain text.

WHAT I BUILT

Conversation, compiled to actions.

The engineering decisions that make it work.

01

Groq function calling core

Built on the Groq Chat Completions API with declared tool definitions — the model decides which tool to call and with what arguments, and the agent executes and responds. Default model openai/gpt-oss-120b, overridable via environment.

02

A practical tool set

get_current_time and add_numbers for quick answers, plus list_upcoming_events — real Google Calendar data through OAuth, so “what’s on today?” returns your actual schedule.

03

CLI UX that respects flow

An interactive REPL for back-and-forth, and single-prompt mode for scripting — myagent “what is 1234 + 5678?”. Installs with pip into a virtualenv, zero ceremony.

04

Credential hygiene by default

API keys and OAuth tokens live in .env, credentials.json and token.json — all gitignored, all documented with placeholders. Secrets never ship with the code.

OUTCOME & LEARNING

What it proved.

OUTCOME

Natural-language calendar control

Ask in English, get your real upcoming events back — the full loop from prompt to tool call to answer works end to end.

OUTCOME

Extensible tool design

Adding a capability means declaring one function — the agent pattern scales without rewriting the core.

LEARNING

Agents are interface design

Function-calling schemas, OAuth flows and CLI ergonomics — the hard part of an agent isn’t the model, it’s the contract between language and tools.
